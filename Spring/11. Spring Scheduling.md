

## What is Scheduling in Spring Boot?

Imagine you have some code that should run automatically at a specific time or interval without a user calling an API.

Examples:

- Send daily email reports at 9 AM
- Clean old logs every night
- Refresh cache every 10 minutes
- Process pending payments every 5 minutes
- Generate analytics reports every hour

Instead of calling an API manually, Spring can execute methods automatically.

This is called **Scheduling**.

---

### Real Life Example

Suppose you have an e-commerce application.

### Without Scheduling

Customer places order → Order stored.

Now some orders remain in `PENDING_PAYMENT` status.

How will they be checked?

One option:

- Admin manually clicks a button every hour.

Bad idea.

### With Scheduling

Every 10 minutes:

```
checkPendingPayments();
```

runs automatically.

---


##  How Scheduling Works Internally

When application starts:

```
@EnableScheduling
```

tells Spring:

> "Look for scheduled methods."

Spring creates a scheduler thread pool.

It continuously monitors time.

When scheduled time arrives:

```
@Scheduled(...)
public void runJob() {
}
```

Spring invokes the method automatically.

```
Application Start
      |
      v
Spring Scheduler Started
      |
      v
Checks schedule
      |
      v
Time reached?
      |
     Yes
      |
      v
Execute method
```

---

## Enable Scheduling

```
@SpringBootApplication
@EnableScheduling
public class Application {
}
```

Without this:

```
@Scheduled
```

will not work.

---

### First Example

```
@Component
public class ReportJob {

    @Scheduled(fixedRate = 5000)
    public void sendReport() {
        System.out.println("Running...");
    }
}
```

Output:

```
Running...
Running...
Running...
```

every 5 seconds.

## Types of Scheduling

There are 3 common types.


### A. fixedRate

```
@Scheduled(fixedRate = 5000)
```

Means:

```
Run every 5 seconds
```

Start time is considered.

Example:

```
@Scheduled(fixedRate = 5000)
public void processOrders() {}
```

Timeline:

```
0 sec  -> Start
5 sec  -> Start
10 sec -> Start
15 sec -> Start
```

Even if previous task is still running.

---

#### Interview Line

> fixedRate schedules task based on start time of previous execution.

---

### B. fixedDelay

```
@Scheduled(fixedDelay = 5000)
```

Means:

Wait for completion first.

Example:

```
@Scheduled(fixedDelay = 5000)
public void syncData() {}
```

Timeline:

```
Start
 |
3 sec execution
 |
Finished
 |
Wait 5 sec
 |
Start again
```

---

#### Interview Line

> fixedDelay schedules task after previous execution completes.

---

### C. initialDelay

```
@Scheduled(
    fixedRate = 5000,
    initialDelay = 10000
)
```

Means:

```
Application starts
Wait 10 sec
Then start scheduler
```

## What is Cron?

Cron is a scheduling expression.

Instead of:

```
Every 5 seconds
```

You can say:

```
Every day at 9 AM
```

Example:

```
@Scheduled(cron = "0 0 9 * * *")
```

Meaning:

```
9:00 AM every day
```

---

### What is Cron Job?

A **Cron Job** is simply:

> A task executed according to a Cron expression.

Example:

```
@Scheduled(cron = "0 0 0 * * *")
public void generateReport() {

}
```

This method is a Cron Job.

---

### Cron Format ??

Spring uses:

```
Second Minute Hour Day Month DayOfWeek
```

Example:

```
0 0 9 * * *
```

Breakdown:

```
0    -> second
0    -> minute
9    -> hour

*    -> every day
*    -> every month
*    -> every weekday
```

Meaning:

```
9 AM daily
```

---

### Common Cron Expressions

#### Every minute

```
@Scheduled(cron = "0 * * * * *")
```

---

#### Every hour

```
@Scheduled(cron = "0 0 * * * *")
```

---

#### Every midnight

```
@Scheduled(cron = "0 0 0 * * *")
```

---

#### Every Monday

```
@Scheduled(cron = "0 0 9 * * MON")
```

9 AM every Monday.

## Scheduling vs Cron Job

Many beginners get confused.

### Scheduling

A broad concept.

```
Run task automatically
```

Includes:

- fixedRate
- fixedDelay
- Cron

---

### Cron Job

A specific type of scheduling.

```
Scheduling
   |
   +--- fixedRate
   |
   +--- fixedDelay
   |
   +--- Cron Job
```

So:

> Every Cron Job is Scheduling, but every Scheduling task is not a Cron Job.

## Production Problem (Very Important)

Suppose:

```
@Scheduled(cron = "0 * * * * *")
```

runs every minute.

Now you deploy:

```
Instance-1
Instance-2
Instance-3
```

All three execute the same job.

Result:

```
Email sent 3 times
```

Bad.

---

### Solution

Distributed Locking

Popular choices:

- Redis Lock
- ShedLock
- Database Lock

Example:

```
@SchedulerLock(name = "report-job")
```

Only one server executes.

This is a common senior-level interview discussion.

## Interview Answer

### What is Scheduling in Spring Boot?

> Scheduling is a mechanism that allows tasks to execute automatically at predefined intervals or times without user intervention. Spring Boot provides scheduling support through `@EnableScheduling` and `@Scheduled`.

### What is Cron Job?

> A Cron Job is a scheduled task that runs according to a Cron expression, such as running every day at 9 AM or every Monday.

### Difference between Scheduling and Cron Job?

> Scheduling is the overall concept of automatic task execution. Cron Job is one implementation of scheduling based on calendar/time expressions. Spring scheduling supports `fixedRate`, `fixedDelay`, and `cron`, where cron is used for time-specific execution.

### Real Production Use Cases?

- Payment retry systems
- Daily report generation
- Cache refresh
- Log cleanup
- Inventory synchronization
- Email notifications
- Data synchronization with external systems

### [Senior Interview Tip]

If asked:

**"Would you use Spring Scheduler for processing millions of orders?"**

Answer:

> No. Spring Scheduler is good for triggering jobs. For large-scale processing, I would use Scheduler → Queue (Kafka/RabbitMQ/SQS) → Worker Services. The scheduler should only trigger the workflow, not perform heavy processing itself.
