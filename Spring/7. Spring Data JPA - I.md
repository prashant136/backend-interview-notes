
# ==JDBC Architecture (From Absolute Beginner Level)

Before learning Spring Data JPA, Hibernate, etc., you must understand JDBC because everything ultimately talks to the database through JDBC.

Think of JDBC as:

> "A bridge between Java application and Database."

Without JDBC, Java cannot directly talk to PostgreSQL, MySQL, Oracle, etc.

---

## 1. What is JDBC?

**JDBC = Java Database Connectivity**

It is a Java API that allows Java applications to:

- Connect to database
- Execute SQL queries
- Retrieve data
- Update data
- Delete data

---

### Real World Example

Suppose you have:

```
Java Application
      |
      |
    JDBC
      |
      |
 PostgreSQL
```

User requests:

```
Get Employee Details
```

Java cannot understand PostgreSQL language directly.
JDBC acts as translator.

---

### Why JDBC Needed?

Without JDBC:

```
Database-specific code
```

For PostgreSQL:

```
postgres code
```

For MySQL:

```
mysql code
```

For Oracle:

```
oracle code
```

Very difficult.

JDBC provides common API:

```
Connection
Statement
PreparedStatement
ResultSet
```

Only driver changes.

## 2. DriverManager

DriverManager is responsible for:

```
Finding the correct database driver
Creating connection to database
```

You say:

```

```

DriverManager finds:

```
PostgreSQL Driver
```

and connects you.

---
### Example

```
Connection con =
DriverManager.getConnection(
    "jdbc:postgresql://localhost:5432/company",
    "postgres",
    "password"

```

---

### What Happens Internally?

Step 1

DriverManager receives URL.

```
jdbc:postgresql://localhost:5432/company
```

Step 2

Identifies:

```
postgresql
```

Step 3

Loads PostgreSQL JDBC Driver.

Step 4

Creates connection.

Step 5

Returns Connection object.

## 4. PreparedStatement

This is one of the most important interview topics.

---

### What is PreparedStatement?

PreparedStatement is used to execute SQL queries safely.

Example:

```
SELECT * FROM employee
WHERE id = ?
```

Notice:

```
?
```

called placeholder.

---

### Why Not Use Statement?

Bad Practice:

```
String sql = "SELECT * FROM employee WHERE id = " + id;
```

Suppose user enters:

```
1 OR 1=1
```

Generated query:

```
SELECT * FROM employee
WHERE id = 1 OR 1=1
```

Now entire table is exposed.

This is called:

```
SQL Injection
```

Very dangerous.

---

### PreparedStatement Solution

```
PreparedStatement ps =
con.prepareStatement(
    "SELECT * FROM employee WHERE id=?"
);

ps.setInt(1, 1);
```

Database treats:

```
1
```

as value only.

Not SQL code.

---

### Benefits

### 1. Prevents SQL Injection

Most important.

---

### 2. Better Performance

Query is compiled once.

Can be reused many times.

Example:

```
INSERT INTO employee(name,salary)VALUES (?,?)
```

Run 10,000 times.

Database reuses execution plan.

Faster.

---

### Example

```
PreparedStatement ps =
con.prepareStatement(
    "SELECT * FROM employee WHERE id=?"
);

ps.setInt(1, 101);

ResultSet rs = ps.executeQuery();
```

---

### executeQuery()

Used for:

```
SELECT
```

returns:

```
ResultSet
```

---

### executeUpdate()

Used for:

```
INSERT
UPDATE
DELETE
```

returns:

```
int
```

(number of rows affected)

Example:

```
int rows = ps.executeUpdate();
```

## Interview Answer (2 Minutes)

**What is JDBC?**

> JDBC (Java Database Connectivity) is a Java API used to connect Java applications with relational databases. It provides standard interfaces such as DriverManager, Connection, PreparedStatement, and ResultSet to execute SQL queries and process results.

**JDBC Flow:**

```
DriverManager
    ↓
Connection
    ↓
PreparedStatement
    ↓
Execute SQL
    ↓
ResultSet
```

**PreparedStatement** is preferred because it prevents SQL injection and improves performance through query precompilation.

# ==what is Spring JDBC and connection pool HikariCP.

## Problem with Plain JDBC

Suppose every API request does:

```
Connection con = DriverManager.getConnection(...);
```

Execute query:

```
SELECT * FROM employee
```

Close connection:

```
con.close();
```

---

### Looks Fine Right?

For 1 user:

```
Open Connection
Run Query
Close Connection
```

No issue.

---

### Production Scenario

Suppose:

```
1000 users
```

call your API simultaneously.

Each request:

```
Open DB Connection
Execute Query
Close DB Connection
```

---

### What Happens Internally?

Creating a database connection is expensive.

Database must:

```
1. Authenticate user
2. Allocate memory
3. Create session
4. Open network socket
5. Maintain connection state
```

Creating connection may take:

```
10ms - 100ms
```

---

### Imagine

1000 requests:

```
1000 Connection Creations
```

Database becomes slow.

-----
## What is Connection Pool?

A connection pool maintains already-open database connections.

Instead of creating new connection every time:

```
Application
     ↓
Connection Pool
     ↓
Existing Connection
     ↓
Database
```

---

### Without Pool

Request 1

```
Create Connection
Execute Query
Destroy Connection
```

Request 2

```
Create Connection
Execute Query
Destroy Connection
```

Request 3

```
Create Connection
Execute Query
Destroy Connection
```

---

### With Pool

Startup:

```
Create 10 connections
```

Store them:

```
Pool

C1
C2
C3
...
C10
```

Request comes:

```
Borrow C1
```

Query executes.

Return:

```
C1 back to pool
```

No new creation.

Very fast.

---

## What is HikariCP?

HikariCP is the most popular JDBC connection pool.

**HikariCP** is ==a zero-overhead, ultra-fast JDBC connection pool==. It is the default connection pooling framework integrated into **Spring Boot**. Instead of creating and destroying database connections for every query, HikariCP maintains a reusable pool of ready-to-use connections to minimize latency and scale performance.

In modern Spring Boot:

```
Default Connection Pool = HikariCP
```

You don't need to install anything separately.

Spring Boot automatically configures it.

---

### Why HikariCP?

Older pools:

```
DBCP
C3P0
Tomcat Pool
```

were slower.

HikariCP is:

```
Faster
Lighter
Less Memory
High Throughput
```

---

### Internal Working

Startup:

```
Spring Boot Starts
```

Hikari creates:

```
10 connections
```

Example:

```
Pool

Connection-1
Connection-2
Connection-3
...
Connection-10
```

---

User Request:

```
GET /employees
```

Hikari:

```
Give Connection-3
```

Application executes query.

After query:

```
Return Connection-3
```

back to pool.

---

### Configuration

application.properties

```
spring.datasource.url=jdbc:postgresql://localhost:5432/company

spring.datasource.username=postgres

spring.datasource.password=postgres
```

---

Hikari automatically starts.

Default configuration:

```
Maximum Pool Size = 10
```

---

Customize:

```
spring.datasource.hikari.maximum-pool-size=20

spring.datasource.hikari.minimum-idle=5

spring.datasource.hikari.connection-timeout=30000
```

---

### Interview Question

### Why HikariCP?

Answer:

> Creating database connections is expensive. HikariCP maintains a pool of reusable connections, reducing connection creation overhead and improving application performance and scalability.

## Interview Answer

### What is HikariCP?

> HikariCP is a high-performance JDBC connection pool used by Spring Boot by default. It maintains reusable database connections, reducing the overhead of creating new connections for every request and improving application performance.

### What is Spring JDBC?

> Spring JDBC is a Spring module that simplifies JDBC programming by removing boilerplate code such as connection management, statement creation, exception handling, and resource cleanup. Its central class is JdbcTemplate.

### How Spring JDBC Works?

```
JDBC
  ↓
HikariCP
  ↓
Spring JDBC
  ↓
JPA
  ↓
Hibernate
```

The `JdbcTemplate` obtains a connection from HikariCP, executes SQL using JDBC internally, maps the result, and returns the connection back to the pool automatically.

## Problem With JDBC

Suppose you have an Employee table.

```
CREATE TABLE employee (
    id BIGINT,
    name VARCHAR(100),
    salary DECIMAL
);
```

Java class:

```
public class Employee {

    private Long id;
    private String name;
    private Double salary;
}
```

---

### JDBC Approach

To save employee:

```
String sql =
    "INSERT INTO employee(id,name,salary) VALUES(?,?,?)";

PreparedStatement ps =
    connection.prepareStatement(sql);

ps.setLong(1, employee.getId());
ps.setString(2, employee.getName());
ps.setDouble(3, employee.getSalary());

ps.executeUpdate();
```

---

To fetch employee:

```
String sql =
    "SELECT * FROM employee WHERE id=?";

PreparedStatement ps =
    connection.prepareStatement(sql);

ps.setLong(1, id);

ResultSet rs = ps.executeQuery();

Employee employee = null;

if(rs.next()) {
    employee = new Employee();

    employee.setId(rs.getLong("id"));
    employee.setName(rs.getString("name"));
    employee.setSalary(rs.getDouble("salary"));
}
```

Look carefully.

You are manually doing:

```
Database Row
      ↓
Java Object
```

conversion.

Every single time.

---

Now imagine:

```

Department
Address
Order
Product
Customer
Payment
```

50+ tables.

Thousands of queries.

Lots of boilerplate.

# ==JPA Annotations==
## 1. @Entity

Marks a Java class as a database table.

Without `@Entity`, Hibernate ignores the class.

```
@Entity
public class Employee {

    private Long id;
    private String name;
}
```

Hibernate understands:

```
Employee Class
      ↓
employee Table
```

---

### Example

```
@Entity
public class Product {

    @Id
    private Long id;

    private String name;

    private Double price;
}
```

Table:

```
product
-------------------
id
name
price
```

---

## 2. @Table

Used when table name differs from class name.

Without @Table:

```
@Entity
public class Employee {
}
```

Hibernate assumes:

```
employee
```

table.

---

### Example

```
@Entity
@Table(name = "employees")
public class Employee {

}
```

Now Hibernate maps:

```
Employee Class      ↓employees Table
```

---

## 3. @Id

Marks Primary Key.

Every Entity must have one.

```
@Entity
public class Employee {

    @Id
    private Long id;

    private String name;
}
```

Database:

```
employee
----------------
id (PK)
name
```

---

## 4. @GeneratedValue

### Why Needed?

Auto-generates IDs.

Instead of:

```
employee.setId(1L);
```

Database generates it.

---

### Example

```
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

Insert:

```
Employee emp = new Employee();
emp.setName("Prashant");

repository.save(emp);
```

Generated SQL:

```
INSERT INTO employee(name)VALUES('Prashant');
```

Database automatically creates:

```
id = 1
```

---


#### [GenerationType. IDENTITY]

Most common in PostgreSQL and MySQL. Most Spring Boot projects use.

```
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

Database column:

```
id BIGSERIAL PRIMARY KEY
```

or

```
id SERIAL PRIMARY KEY
```


#### Why use IDENTITY?

Because database is responsible for generating unique IDs.

Benefits:

```
No duplicate IDs
Thread-safe
Works in distributed systems
Easy to maintain
```

#### What is @GeneratedValue?

> `@GeneratedValue` tells JPA/Hibernate that the primary key value should be generated automatically instead of being manually assigned by the application.
---

## 5. @Column

Maps field to column.

Useful when column names differ.

---

Without @Column

```
private String name;
```

maps to:

```
name
```

column.

---

With @Column

```
@Column(name = "employee_name")
private String name;
```

maps to:

```
employee_name
```

---

### Example

```
@Entity
public class Employee {

    @Id
    private Long id;

    @Column(name = "employee_name")
    private String name;
}
```

---

## 6. @Transient

Ignore field.

Hibernate will not store it in DB.

---

Example:

```
@Entity
public class Employee {

    @Id
    private Long id;

    private String name;

    @Transient
    private String tempPassword;
}
```

Database:

```
employee
------------
id
name
```

No column:

```
tempPassword
```

---

### Production Use Case

```
@Transient
private String confirmPassword;
```

Used only for validation.

Not stored.

---

## 7. @CreationTimestamp

Automatically stores creation time.

---

Example

```
@CreationTimestamp
private LocalDateTime createdAt;
```

Insert:

```
repository.save(employee);
```

Hibernate:

```
createdAt = current timestamp
```

automatically.

---

Database

```
2026-06-12 10:30:00
```

---

## 8. @UpdateTimestamp

Automatically updates timestamp whenever row changes.

---

```
@UpdateTimestamp
private LocalDateTime updatedAt;
```

Whenever update occurs:

```
employee.setName("Updated");
repository.save(employee);
```

updatedAt changes automatically.

---

## 9. @Enumerated

Used with Enum.

---

Without it:

```
private Status status;
```

Hibernate doesn't know how to store it.

---

Enum

```
public enum Status {

    ACTIVE,
    INACTIVE
}
```

---

### Example

```
@Enumerated(EnumType.STRING)
private Status status;
```

Database:

```
ACTIVE
```

instead of

```
0
```

---

Always use:

```
EnumType.STRING
```

Production best practice.

# Relationship Annotations

These are extremely important.

---

## 10. @OneToOne

One record related to one record.

---

Example

```
Person
   ↔
Passport
```

One person:

```
1 passport
```

One passport:

```
1 person
```

---

```
@Entity
public class Passport {

    @Id
    private Long id;
}
```

```
@Entity
public class Person {

    @Id
    private Long id;

    @OneToOne
    private Passport passport;
}
```

---

## 11. @OneToMany

One parent, many children.

---

Example

```
Customer
      ↓
Many Orders
```

---

Customer:

```
@Entity
public class Customer {

    @Id
    private Long id;

    @OneToMany
    private List<Order> orders;
}
```

---

Database

```
Customer 1
   |
   |---- Order 1
   |---- Order 2
   |---- Order 3
```

---

## 12. @ManyToOne

Most commonly used annotation.

---

Example

```
Many Employees
       ↓
One Department
```

---

```
@Entity
public class Employee {

    @Id
    private Long id;

    @ManyToOne
    private Department department;
}
```

---

```
Employee A → IT

Employee B → IT

Employee C → IT
```

Many employees belong to one department.

---

## 13. @JoinColumn

Specifies Foreign Key column.

---

Without it

Hibernate generates column name itself.

---

Example

```
@ManyToOne
@JoinColumn(name = "department_id")
private Department department;
```

Database:

```
employee
----------------------
id
name
department_id
```

---

### Example 1 (Most Common Entity)

```
@Entity
@Table(name = "employees")
public class Employee {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "employee_name")
    private String name;

    private Double salary;

    @CreationTimestamp
    private LocalDateTime createdAt;

    @UpdateTimestamp
    private LocalDateTime updatedAt;
}
```

---

### Example 2 (Employee → Department)

```
@Entity
public class Department {

    @Id
    private Long id;

    private String name;
}
```

```
@Entity
public class Employee {

    @Id
    private Long id;

    private String name;

    @ManyToOne
    @JoinColumn(name = "department_id")
    private Department department;
}
```

---

Database

```
department
--------------
id
name
```

```
employee
--------------
id
name
department_id
```

---

### Example 3 (Customer → Orders)

```
@Entity
public class Customer {

    @Id
    private Long id;

    private String name;

    @OneToMany
    private List<Order> orders;
}
```

```
@Entity
public class Order {

    @Id
    private Long id;

    private Double amount;
}
```
